# PR 규칙 참고

## 이 저장소의 PR을 규칙대로 고쳐 쓰면

### PR #1: 목적이 둘 이상인 PR

기록에 남은 PR:

```
제목: docs: CLAUDE.md 및 개선 계획 문서 추가
본문: ## 개요 / ## 변경 사항 (파일별 소제목과 긴 설명) / ## 참고
```

- 제목에 "및"이 들어간다. `CLAUDE.md`, 개선 계획 문서, `.gitignore` 수정이 한 PR에 있다.
- 변경 사항이 문서 내용을 다시 요약하고 있다. 문서는 diff로 읽으면 된다.
- 확인 방법이 "참고"에 섞여 있다.

올바른 형태는 PR 세 개다.

```
chore: build 하위 디렉터리 gitignore 적용
docs: CLAUDE.md 추가
docs: 개선 계획 문서 추가
```

그중 개선 계획 문서 PR의 본문:

```markdown
## 개요

정적 분석 리포트를 실제 코드로 다시 확인하고, 개선 작업을 실행 순서대로 정리한다.

## 변경 사항

- `docs/improvement-plan.md` 추가
- 리포트의 크래시 후보는 모두 확인됨. "observe()가 State를 수집하지 않음"은 과장으로 판단
- 리포트에 없던 항목 6건 추가

## 확인 방법

- 코드 변경 없음 (빌드 영향 없음)

## 참고

- 계획의 코드 예시는 빌드해 보지 않았다. 각 Phase PR에서 확인한다.
- Orbit 버전 요구사항은 Maven Central 메타데이터와 12.0.1 릴리즈 노트로 확인했다.
```

### PR #2: 섹션 이름이 규칙과 다른 PR

기록에 남은 PR:

```markdown
## 요약
- 커밋 메시지 규칙을 `/commit` 스킬로 정리
- `SKILL.md`에 커밋 절차, `reference.md`에 타입 선택 기준과 예시

## 규칙 핵심
- 작은 단위로 쪼개기가 최우선
- `타입: 한국어 명사형 제목` 형식, 스코프 없음
- 본문은 이유가 필요할 때만
```

- `요약`, `규칙 핵심`은 정해진 섹션이 아니다.
- 왜 필요한지가 없다.
- 확인 방법이 없다.

올바른 형태:

```markdown
## 개요

기존 커밋이 대부분 `feat`이고 한 커밋에 여러 변경이 섞여 있어, 커밋 규칙을 정하고 `/commit` 스킬로 강제한다.

## 변경 사항

- `SKILL.md`: 커밋 절차 (변경 파악 → 계획 → 확인 → 빌드 → 커밋)
- `reference.md`: 타입 판정표, 이 저장소 커밋을 고쳐 쓴 예시
- 규칙 핵심: 작은 단위 최우선, `타입: 한국어 명사형 제목`, 스코프 없음

## 확인 방법

- 코드 변경 없음 (빌드 영향 없음)
```

## 제목

| 나쁜 예 | 좋은 예 | 이유 |
|---|---|---|
| `Phase 2 작업` | `refactor: MVI를 Orbit으로 전환` | 타입이 없고 무엇인지 알 수 없음 |
| `refactor: Orbit 전환 및 테스트 추가` | `refactor: MVI를 Orbit으로 전환` | 테스트는 전환의 일부. 목적이 하나면 제목도 하나 |
| `fix: 크래시 수정 및 배경색 수정` | `fix: PokemonPagingSource 네트워크 에러 크래시 수정` + `fix: PokemonDetail 배경색 폴백 값 수정` | 목적이 둘이면 PR을 나눔 |
| `feat(detail): 서식지 표시` | `feat: PokemonDetail 서식지 정보 표시` | 스코프를 쓰지 않음 |

단, 관련된 작은 수정 여러 개를 한 번에 올리는 PR은 목적 하나로 본다. 이때 제목은 묶음 전체를 말한다.

```
fix: Phase 0 크래시·오동작 수정
```

## 변경 사항

커밋이 여러 개면 커밋 헤더를 그대로 나열한다. 순서도 커밋 순서를 따른다.

```markdown
## 변경 사항

- build: orbit-mvi 의존성 추가
- refactor: PokemonDetailViewModel Orbit 컨테이너로 전환
- test: PokemonDetailViewModel 테스트 추가
- refactor: MainViewModel Orbit 컨테이너로 전환
- refactor: 커스텀 MVI base 패키지 삭제
```

## 확인 방법

해본 것만 체크한다. 체크하지 않은 항목에는 이유를 붙인다.

```markdown
## 확인 방법

- [x] `./gradlew assembleDebug` 성공
- [x] `./gradlew testDebugUnitTest` 성공
- [ ] 실기기에서 목록 스크롤 후 상세 진입 (에뮬레이터 없음)
```

| 나쁜 예 | 이유 |
|---|---|
| `- 테스트 완료` | 무엇을 어떻게 확인했는지 알 수 없음 |
| `- [x] 실기기 확인` (실제로는 안 함) | 우선순위 2번 위반 |
| 섹션 생략 | 코드 변경이 없어도 `코드 변경 없음 (빌드 영향 없음)`을 적음 |
